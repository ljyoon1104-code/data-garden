고등학생과 교사의 데이터 과학 탐구를 위한 React·TypeScript·Vite 정적 PWA입니다. 데이터 / 정리 / 시각화 / 분석 / 결과를 자유롭게 이동합니다. 파일과 프로젝트는 기기 안에서 처리하며 업로드 서버·로그인·동기화·외부 폰트·런타임 CDN을 사용하지 않습니다.

- 저장소: https://github.com/ljyoon1104-code/data-garden (main)
- 배포 주소: https://ljyoon1104-code.github.io/data-garden/ (배포 검증 결과는 docs/stage-10-verification.md)
- 2026-10-16 실제 Pages 배포·HTTPS 실행 확인. 타입 검사·273개 테스트·빌드·캐시 검증 통과. PDF 저장·독립 HTML 열기·실제 HTTPS 오프라인/OS 설치 등 남은 수동 검증은 [검증 기록](docs/stage-10-verification.md)에 명시했습니다.
- 과거 개발 기록: [1~9단계 개발 당시 기록](docs/archive/stages-1-9.md). 당시 처리 기준·한도·검증 결과를 보관하며, 현재 사용법은 이 README를 따릅니다.
- 2026-11-10 로컬 보안 보강과 재검증: [입력·복원·출력 검증 기록](docs/security-verification.md). 현재 미커밋 소스의 검사이며 Pages 재배포 기록과 구분합니다.

## 실행

Node.js 24 LTS 권장(22.12 이상 지원).

~~~sh
npm ci
npm run dev
npm run typecheck
npm test
npm run build
npm run check:build
npm run serve:production -- 4173
~~~

개발: http://127.0.0.1:5173/ · 프로덕션: http://127.0.0.1:4173/data-garden/ · 임의 하위 경로: http://127.0.0.1:4173/verification-10/ . 개발 모드에서는 Service Worker를 등록하지 않습니다. 빌드는 dist만 정적 서버에 배포합니다.

Windows에서는 `데이터뜰_실행.bat`를 두 번 클릭하면 빌드 후 `127.0.0.1:4211`에서 실행합니다. 서버가 직접 수신에 성공한 뒤 브라우저를 엽니다. 포트를 이미 쓰고 있으면 다른 서버를 데이터뜰로 간주하거나 포트를 자동 변경하지 않고 종료 안내를 표시합니다. 로컬 서버의 `dist`는 실제 폴더여야 하며, 내부의 심볼릭 링크·정션을 통한 파일 제공도 허용하지 않습니다. 자세한 범위는 [Windows 로컬 서버 검증](docs/local-server-security-verification.md)을 참고하세요.

Windows 제한된 실행 환경에서 Vitest 임시 경로 ENOENT가 발생하면 프로젝트의 tmp 폴더를 만들고 현재 터미널의 TEMP와 TMP를 해당 절대 경로로 지정한 뒤 재실행하세요. 앱 코드 검증 실패와 구분합니다.

## 사용

1. 데이터: CSV(UTF-8/BOM/EUC-KR) 또는 XLSX를 미리 보고 불러옵니다. XLSX는 목록에서 시트를 선택한 뒤 미리봅니다. 값·속성을 확정 편집하며 원본과 과거 버전은 유지합니다.
2. 정리: 결측·중복·이상값·스케일, 계산 열·날짜·결합·집계를 미리 보고 확정합니다.
3. 시각화: 산점도·히스토그램·상자·막대·선·원·영역·열지도 8종과 계산 근거를 확인합니다.
4. 분석: 회귀(선형·트리·이웃), K-means 군집, 연관 규칙을 저장 조건·행·전처리·분할·seed와 함께 탐구합니다.
5. 결과: 전체 저장 결과를 종류·자료·조건으로 찾고, 당시 상세·비교·해석·표 출력·보고서를 엽니다. 최신 여부는 해당 결과 자료의 활성 버전과 저장 분석 조건으로 판정합니다.

해석은 프로젝트·그래프·분석에 작성하고 명시적으로 저장/취소합니다. 예제 해석은 별도 표시합니다. 자료 수정은 되돌리기/다시 실행과 연결되며, 해석·출력은 원자료나 모델을 변경하지 않습니다.

## 내보내기와 보고서

- 자료 CSV/XLSX: 전체·필터·선택 행, 전체·선택 열, 현재 정렬 적용을 선택합니다. 페이지에 보이는 행만 출력하지 않습니다. CSV는 UTF-8 BOM과 조건 정보 JSON, XLSX는 여러 표와 정보 시트입니다.
- CSV 안전 처리 기본값: 열 이름과 표의 모든 문자열을 검사합니다. 전각 문자와 보이지 않는 접두사도 탐지하며, 셀 앞에 작은따옴표를 실제로 추가한 개수를 기록합니다. 검사 과정의 정규화는 원문에 적용하지 않으며 숫자 `-5`는 유지합니다. 다른 구분자나 줄바꿈 뒤에서 수식 셀이 생길 수 있는 입력은 CSV 출력을 중단하고 XLSX를 안내합니다. XLSX는 명시적 숫자·문자·불리언 셀이며 수식 셀을 만들지 않습니다.
- 날짜는 시간대 변환 없는 ISO 문자열, 식별자 앞자리 0은 문자로 보존합니다. CSV의 빈 문자열과 null, 표 도구의 자동 형변환·숫자 정밀도에는 제한이 있습니다. 완전한 프로젝트 복원은 JSON 백업을 사용하세요.
- 분석 표: 회귀 평가·평가 행·제외 행, 군집 k·행·거리·SSE·특성 통계·실루엣 방식, 연관 규칙·후보·분자/분모·선택적 변환 거래. 검색 규칙 출력은 모든 일치 페이지입니다.
- PNG: 화면과 같은 ECharts 설정으로 너비 1600px·흰 배경·제목·당시 버전·범위·표본 설명을 포함합니다. 각 집단 버튼은 해당 패널만, 보고서는 모든 집단을 포함합니다.
- 보고서: 결과 선택/순서·질문·해석·표 수록 범위를 정하고 생성 시점에 고정합니다. 그림·스타일을 내장한 단일 HTML이며 외부 스크립트가 없습니다. 인쇄용 화면에서 브라우저의 **PDF로 저장**을 이용합니다. 자동 PDF 파일 생성 기능은 아닙니다.
- 한도: 표 출력 100만 셀·20만 행·32MiB, 보고서 20결과·20그림·12,000표 행·24MiB. 이미지 설명은 5,000자와 높이 제한을 적용합니다. 한도 초과 시 줄일 항목을 안내하고 조용히 잘라서 성공 처리하지 않습니다. 요약 표는 전체/수록 행을 표시합니다.

## 입력과 복원 한도

| 입력 | 한도와 검사 시점 |
| --- | --- |
| CSV | 파일을 열기 전 20 MiB. Worker가 64 KiB 파일 조각을 순서대로 디코딩합니다. 필드당 65,536 UTF-16 코드 단위, 논리 레코드당 1,048,576 코드 단위(인용·구분자 포함), 자료 50,000행, 200열, 머리글과 빈 셀 보정까지 합해 500,000셀을 파싱 도중 검사합니다. |
| XLSX ZIP | 파일 20 MiB, ZIP 항목 1,024개, 선언된 해제 크기 항목당 64 MiB·전체 128 MiB를 먼저 검사합니다. 실제 해제는 압축 입력을 1 KiB씩 공급하며 최대 16 KiB 출력 조각마다 크기를 확인합니다. 요청당 실제 출력 48 MiB, 메타데이터 XML 각 1 MiB, 스타일 4 MiB, 공유 문자열 16 MiB, 선택 시트 32 MiB입니다. 실제 크기와 CRC도 확인합니다. |
| XLSX 시트 | 목록은 통합 문서와 관계 정보만 읽습니다. 미리보기는 선택한 시트와 필요한 공유 문자열·스타일만 읽습니다. SheetJS로 넘기기 전에 시트 범위 50,000행(머리글 제외)·200열·500,000셀, 셀 문자열 32,767 UTF-16 단위, 선택 셀에 반복 참조되는 문자열 합계 16 Mi UTF-16 단위, 표시 형식 작업량 64 Mi 단위를 검사합니다. 검증한 공용 정보와 셀만 새 통합 문서로 구성하며, 이 구성의 전체 XML도 48 MiB로 제한합니다. |
| XLSX XML | 중첩 64단계, 태그·속성 이름 256 UTF-16 단위, 태그당 속성 96개, 속성 값 65,536단위, 스타일 65,536개·숫자 서식 코드 1,024단위, 공유 문자열 500,000개를 각 항목을 읽는 중에 검사합니다. XML 요소는 메타데이터 종류별 2,048~8,192개, 스타일 200,000개, 공유 문자열 1,000,000개, 선택 시트 2,000,000개 이하입니다. |
| JSON 백업 | 읽기 전 80 MiB. 손상된 UTF-8을 거절하고, `JSON.parse` 전에 파일 전체에 중첩 64단계, 1,200만 토큰(키·값·컨테이너), 문자열당 1,048,576 UTF-16 코드 단위, 숫자·리터럴당 128 코드 단위를 적용합니다. 이후 작업 공간 자체의 중첩 60단계·2,000만 노드, 원본과 모든 버전의 보존 셀 300만 개 한도도 적용합니다. |
| JSON 복원 계산 | 프로젝트 전체에 검증 작업량 3,000만 단위를 적용합니다. 자료 크기, 버전과 작업 참조, 가공 설정의 반복 횟수와 재계산, 저장 분석, 그래프가 읽는 행과 히스토그램 구간 수에 따라 차감합니다. 회귀 모델 평가·군집 이력과 실루엣·연관 검증도 같은 예산을 사용하며, 반복 검증되는 작업 설정과 속성 설명의 크기도 포함합니다. 검증 비용을 해당 재계산 전에 예약하므로 같은 자료·계보·분석을 반복 참조해도 각각 예산을 소모합니다. 경과 시간이나 PC 속도로 판정하지 않습니다. |

입력·복원이 한도를 넘으면 자료나 프로젝트를 나누어 다시 시도하세요. 오류 또는 취소 뒤에는 기존 프로젝트를 계속 사용할 수 있습니다. 완전히 검증된 미리보기를 확인한 뒤에만 자료나 복원 사본이 등록됩니다.

CSV 입력은 파일 전체를 먼저 읽거나 전체 레코드를 만든 뒤 한도를 확인하지 않습니다. 64 KiB 조각을 읽는 도중 행·열·빈 셀 보정 범위가 한도를 넘으면 이후 파일 조각을 읽기 전에 중단합니다. CSV 출력도 최종 문자열을 만들기 전에 UTF-8 바이트, 인용부호 이스케이프, BOM·구분자·줄바꿈과 보호 접두사 크기를 누적해 32 MiB를 검사합니다.

XLSX의 압축 해제와 XML 사전 검사를 위해 pako 2.1.0과 saxes 6.0.0(xmlchars 2.2.0)을 사용합니다. 브라우저 번들과 오프라인 캐시에 포함하며 라이선스는 public/licenses에 보관합니다. 실제 해제 바이트 한도는 전체 JavaScript 힙의 최대 크기와는 다릅니다. XML·자료 객체·표시용 사본에 추가 메모리가 필요합니다. 시트 경고는 가변 열의 행 번호 30개, 잘못된 날짜 셀 5개까지만 자세히 표시하고 나머지는 정확한 개수로 안내합니다. 원본 행·셀은 모두 보존합니다.

암호화·ZIP64와 일부 비표준 ZIP 구조는 입력에서 거절합니다. 일반 XLSX로 다시 저장한 사본을 사용하세요. Excel 16.0.10417.20228의 구형 텍스트 가져오기 마법사는 인용된 단독 LF를 추가 행으로 나누고 일부 행만 읽는 호환성 문제가 있습니다. 셀 안 줄바꿈은 현대식 텍스트/CSV 가져오기 또는 XLSX를 사용하세요. 실제 Excel에서 현대식 CSV 27개·구형 마법사 대조 CSV 24개·XLSX 53개 가상 사례를 저장·닫기·재열기한 뒤 수식 셀 0개와 보호 문자열 유지를 확인했습니다. CSV 자동 자료형 추론에는 차이가 있으며, 명시적 XLSX는 실제 숫자와 숫자 모양 문자열 및 LF/CR/CRLF를 보존했습니다. 다른 Excel 버전·지역 설정과 LibreOffice는 미검증입니다. 자세한 조건과 파일 해시는 [보안 재검증 기록](docs/security-verification.md)을 참고하세요.

## 도움말·예제

‘도움말 · 가상 예제’에서 필요한 설명만 열 수 있습니다. 가상 예제 4개는 현재 엔진으로 생성한 결과를 포함하며 새 프로젝트 사본으로 열립니다. 열 때 모델을 재학습하지 않습니다.

- 날짜/정리/계산/결합/집계: 월별 합계 6g·10g.
- 회귀 단순/다중 세 모델: 생성식 Y=3+2X−4Z, 다중 선형 회귀 계수 독립 검증.
- 군집 k=2·3: k=2 SSE=1, 정확 실루엣 독립 검증.
- 연관: 6거래 중 빈 거래 2개, 양쪽 복합 규칙의 개수·지표 검증.

재생성: npm run examples:generate. public/examples는 직접 만든 가상 교육 자료(CC0)이며 실제 학생 자료가 아닙니다. 의존성 라이선스는 public/licenses에 포함합니다. 앱 소스의 별도 라이선스는 지정하지 않았습니다.

## 저장·오프라인·공용 PC

IndexedDB에 확정 상태를 자동 저장합니다. JSON 백업은 별도 파일입니다. 읽기 전용 탭에서는 조회·출력만 가능하고 편집·실행은 막습니다. 업데이트는 저장 성공 후 명시적으로 적용하며 구 탭의 파일 캐시를 보호합니다. 사용자 자료는 Service Worker 캐시에 넣지 않습니다. 주소 경로별 저장소·캐시는 분리됩니다. 주소를 옮길 때 기존 주소에서 JSON 백업 후 새 주소에서 복원하세요.

공용 PC에서는 필요한 백업을 받은 뒤 **프로젝트 관리 → 공용 PC · 사용자 자료와 설정 지우기**를 사용하세요. 이 배포 경로의 프로젝트와 저장된 화면 설정을 지웁니다. 수정본으로 열린 탭은 삭제를 확인하면 화면·선택·준비 중인 출력을 비우며, 삭제 전 자동 저장 요청은 자료를 다시 만들 수 없습니다. 앱 프로그램 캐시, 다른 배포 경로의 저장소, 이미 내려받은 백업·출력 파일은 유지됩니다. 공용 PC에 남은 다운로드 파일은 필요에 따라 별도로 정리하세요. 자세한 범위는 [공용 PC 전체 삭제 검증](docs/public-pc-reset-verification.md)을 참고하세요.

현재 수정본은 IndexedDB 연결 버전을 2로 올려 공개 구버전(연결 버전 1)의 재저장을 차단합니다. 이행 자체는 프로젝트를 삭제하지 않으며 프로젝트 스키마·JSON 백업 형식을 바꾸지 않습니다. **이미 실행 중인 구버전 탭의 화면과 JSON 백업은 남을 수 있으므로 공용 PC를 떠나기 전에 모든 구버전 탭을 닫아야 합니다.** 구버전 쓰기 탭이 잠금을 유지하면 필요한 백업을 받은 뒤 그 탭을 닫고 수정본 탭을 새로고침하세요. 저장소 연결이 10초 안에 완료되지 않거나 업데이트가 차단되면 오류를 안내하며, 삭제 성공으로 처리하지 않습니다. 다른 탭을 닫은 뒤 재시도하세요. 혼용 조건과 남은 제한은 [구버전·수정본 혼용 검증](docs/mixed-version-reset-verification.md)에 기록합니다.

## 배포

GitHub Settings → Pages → Source는 GitHub Actions를 사용합니다. 워크플로는 지정 저장소의 main push 또는 main 수동 실행만 허용합니다. Node 24에서 npm ci → 타입 검사 → 전체 테스트 → 빌드 → 캐시 검사 → 산출물 경계 검사 후 dist만 Pages artifact로 올립니다. 빌드는 contents: read만 사용하며 checkout 인증을 유지하지 않습니다. 성공한 빌드에 의존하는 별도 배포 작업에만 Pages 쓰기·OIDC 권한을 부여합니다. Actions는 공식 릴리스와 대조한 SHA로 고정했습니다.

Git 제외 규칙과 배포 파일 검사는 별개입니다. 산출물 검사는 예상하지 않은 파일·폴더, 링크·하드링크, 사전 캐시 불일치를 거절합니다. 예제·라이선스·자산 형식을 바꿀 때는 허용 목록도 함께 검토해야 합니다. 확인한 원격 상태, 미확인 보호 설정과 이번 로컬 수정의 검증 범위는 [GitHub Actions 보안 검증](docs/github-actions-security-verification.md)에 기록했습니다.
