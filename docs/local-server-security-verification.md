# Windows 실행 배치·프로덕션 로컬 서버 검증

검증일: 2026-11-11. 가상 표식 파일, 별도 포트와 임시 폴더로만 점검했다. 커밋·푸시·배포·호스트 설정은 변경하지 않았다.

## 수정 전 재현

- 배치 파일은 빌드 후 `npm run serve:production -- 4211`을 실행했다. 서버 기본 명령의 포트는 4173이며 수신 주소는 `127.0.0.1`로 고정돼 있었다. 별도 서버의 실제 소켓과 Windows 수신 목록에서도 IPv4 루프백만 확인했다. 수신 목록의 원격 주소 자리인 `0.0.0.0:0`을 바인딩 주소로 해석하지 않았다.
- TCP 요청 줄을 직접 작성했고, 시험용 관찰 코드로 Node가 받은 `req.url`도 대조했다. URL 파서나 HTTP 클라이언트가 먼저 경로를 정규화하는 시험이 아니다. `..`·인코딩·역슬래시·혼합 구분자 우회는 수정 전에도 외부 표식 파일을 제공하지 않았다.
- 반면 `dist` 안에 외부 폴더를 가리키는 Windows 정션을 만들면 외부 표식 파일이 200으로 제공됐다. 루트와 `/data-garden/` 모두에서 재현했다.
- 기존 배치의 서버 판별 부분에 같은 HTML 제목을 반환하는 가상 서버를 연결하자 정상 데이터뜰 서버로 판정했다. 실제 사용자 서버를 대상으로 시험하지 않았다.

## 수정 내용

- 원본 요청 경로를 한 번만 디코딩하며, 경로 탐색·Windows 구분자·ADS·특수 장치명·끝의 점/공백 별칭을 거절한다.
- `dist` 자체와 요청 경로의 각 구성 요소에서 정션·심볼릭 링크를 거절한다. 실제 경로가 루트 안에 있는지 확인하고 파일을 연 뒤에도 경로와 파일 식별 정보를 재확인한다.
- 루프백 바인딩을 유지하고 외부 호스트명, 누락·중복된 Host 헤더를 거절한다. 이 검사는 DNS 재바인딩에 대한 추가 방어이며 실제 브라우저 공격을 재현했다는 뜻은 아니다.
- 배치는 기존 서버의 제목만 보고 브라우저를 열지 않는다. 직접 띄운 서버가 포트 바인딩에 성공한 다음에만 브라우저 열기를 요청한다. 사용 중인 포트에서는 오류를 표시하고 기존 서버를 종료하거나 재사용하지 않는다.
- 기본 배치 포트 4211, 직접 실행 포트 4173과 기존 하위 경로는 유지한다. 명시적인 포트 인자 0은 시험을 위해 운영체제가 선택한 포트를 사용하며 실제 포트를 출력한다.

## 수정 후 검증

| 항목 | 결과 |
| --- | --- |
| 실제 수신 주소 | 배치 시험은 `127.0.0.1:61993`, 브라우저 시험은 `127.0.0.1:64267` 하나만 LISTENING이었다. 기본 루프백 바인딩은 수정 전후 같다. |
| 외부 표식 파일 | 수정 전 정션 경로는 200이었으나 수정 후 루트·하위 경로에서 404였다. 내부로 연결한 정션도 거절하고, `dist` 자체가 정션이면 서버를 시작하지 않는다. |
| 원본 요청 경로 | 정규화하지 않은 TCP 요청 25종에서 경로 탐색·인코딩·역슬래시·혼합 구분자·ADS·장치명·별칭을 거절했다. Node의 실제 요청 경로도 보낸 값과 일치했다. |
| 정상 요청 | 루트와 기존 세 하위 경로는 200, 끝 슬래시가 없는 마운트는 302였다. JS·CSS·인코딩된 한글 파일명도 정상 응답했다. |
| 실행 배치 | 고정 포트 4211만 시험 포트로 바꾼 격리 복사본으로 실제 빌드·서버 실행을 확인했다. 같은 제목의 서비스가 포트를 쓰면 종료 코드 1로 실패했다. |
| 브라우저 열기 시점 | 시험용 프로세스 관찰로 자신의 서버 수신 이후에만 브라우저 열기를 요청하고 실제 루프백 URL을 전달하는지 확인했다. 포트 충돌 때는 호출하지 않았다. |
| 실제 Edge 157 | 별도 프로필의 5개 단계가 통과했다. 진입·새로고침과 JS/CSS·manifest·Worker·예제 요청이 정상이며, 날짜 예제의 실제 Worker 복원·저장·재접속을 확인했다. 콘솔·페이지 오류와 실패 요청은 0개였다. |
| Service Worker | 범위는 `/data-garden/`이며 사전 캐시 28개에 Worker와 예제가 포함됐다. |

타입 검사, 전체 테스트 **370개 통과·1개 건너뜀**, 기존 검증 자료 **26개 일치**, 격리 복사본에서의 빌드·캐시 검사, `git diff --check`가 통과했다. 이번 서버 회귀 시험은 32개 통과·1개 건너뜀이며, 전체 개수에 포함된다. 검증용 복사본의 테스트는 원본 시험 수집에 섞이지 않도록 분리한 뒤 최종 원본 전체 시험을 실행했다.

실행 중인 사용자 서버의 자산을 바꾸지 않기 위해 빌드는 격리 복사본에서만 수행했다. 원본 `dist` 29개 파일의 전후 SHA-256은 모두 같았고, 기존 사용자 서버·브라우저 프로필은 사용하거나 종료하지 않았다. 수정본은 다음 서버 실행부터 적용된다.

가상 시험 스크립트와 원본 결과는 Git에서 제외되는 `tmp/local-server-baseline-qyiXKN`, `tmp/local-launcher-baseline-knvyz7`, `tmp/batch-launch-audit-32arVN`, `tmp/local-server-edge-phNT2A`에 보관했다.

## 검증 범위의 한계

Windows에서 파일 심볼릭 링크 생성 권한이 없어 해당 시험은 건너뛰었다. 디렉터리 정션, 내부 목적지 링크와 루트 자체가 링크인 경우는 실제 시험했다. 다른 PC에서의 접속 시험이나 DNS 재바인딩 브라우저 공격은 수행하지 않았다. 기본 사용자 프로필의 자동 브라우저 열기는 `DATA_GARDEN_NO_BROWSER=1`로 제외했고, 열기 조건은 시험용 대체 프로세스와 독립 Edge 실행으로 나누어 확인했다. 이 서버는 신뢰하는 로컬 빌드 산출물을 확인하기 위한 서버이며, 파일을 동시에 변조할 수 있는 로컬 프로세스를 격리하는 보안 경계로 사용하지 않는다.
