# 공용 PC 전체 삭제 검증

검증일: 2026-11-11. 로컬 수정과 가상 자료로만 확인했다.

## 수정 전 재현

- 독립 Edge 프로필에서 같은 주소의 쓰기 탭과 읽기 전용 탭을 열었다. 쓰기 탭에서 전체 삭제 버튼으로 IndexedDB의 프로젝트를 0개로 만들었지만, 읽기 전용 탭에 삭제 전 자료가 남았고 그 내용의 JSON 백업도 내려받을 수 있었다.
- 정상 두 탭은 쓰기 잠금 때문에 동시에 자동 저장하지 않는다. 저장 경계의 결함은 별도로 확인했다. 두 개의 저장소 연결과 독립 저장 큐에서 삭제 전 프로젝트 사본을 보관한 뒤, 한 연결에서 삭제하고 다른 연결에서 이전 사본을 저장하자 삭제된 프로젝트가 다시 만들어졌다.

## 수정과 적용 범위

- 전체 삭제는 프로젝트 본문과 목록·최근 선택 등 메타데이터를 비운다. 같은 IndexedDB 트랜잭션에서 빈 저장소임을 나타내는 초기화 표시와 새로운 삭제 세대를 남긴다. 프로젝트 자료를 담지 않는 두 표시만 유지하므로 재접속해도 샘플을 자동 생성하지 않는다.
- 저장·개별 삭제·전체 삭제는 시작한 세대를 같은 트랜잭션에서 확인한다. 삭제보다 먼저 완료한 쓰기는 전체 삭제에 포함되며, 삭제 뒤 처리되는 이전 세대의 쓰기는 거절된다.
- 다른 탭에는 삭제 커밋 이후에 알린다. 알림 내용 자체로 상태를 바꾸지 않고 IndexedDB를 확인한다. 알림을 놓쳐도 탭 활성화 시와 활성 탭의 주기적인 확인에서 감지한다. 백그라운드 탭은 확인 전에는 화면을 다시 표시하지 않는다.
- 삭제를 확인한 탭은 예약 저장과 작업을 취소하고, 프로젝트·자료 선택·미리보기·준비된 출력 상태를 비운다. 다운로드·인쇄를 시작하기 직전에도 같은 삭제 세대인지 확인한다. 삭제가 실패하면 기존 상태를 유지하고 성공으로 표시하지 않는다.
- 이미 내려받은 파일, 앱 프로그램 캐시, 다른 배포 경로의 프로젝트와 다른 앱 저장소는 삭제하지 않는다. 사용자가 보존한 JSON 백업을 명시적으로 다시 복원하는 것은 가능하다. 이 수정 전 버전으로 열려 있던 탭에는 새 동작이 적용되지 않으므로 공용 PC 사용 후 해당 탭도 닫아야 한다.

## 로컬 브라우저 검증

Edge 157의 별도 프로필과 별도 포트에서 실제 전체 삭제 버튼으로 아래를 확인했다. 가상 프로젝트만 사용했으며 기존 브라우저 프로필·서버는 사용하지 않았다.

| 상황 | 결과 |
| --- | --- |
| 같은 주소의 쓰기·읽기 전용 탭 | 삭제 후 두 탭의 자료·선택을 비웠다. IndexedDB에 프로젝트는 0개, 자료가 없는 초기화·삭제 표시만 남았다. |
| 자동 저장 대기 중 삭제 | 예약을 취소했다. 시험에서 이전 예약 콜백을 다시 실행해도 저장되지 않았다. |
| 저장 트랜잭션 도중 삭제 | 먼저 시작한 저장이 완료된 뒤 삭제 트랜잭션이 완료됐다. 저장했던 프로젝트까지 지워졌으며 이후 되살아나지 않았다. |
| 비활성 상태·알림 누락 | 알림을 차단하고 탭을 동결·재개한 뒤 시험용 활성화 이벤트로 화면을 비웠다. 별도로 활성화 이벤트도 차단한 활성 탭에서 주기적 확인이 삭제를 감지했다. |
| 실제 탭 전환 | 초점 모의를 끈 별도 Edge 프로필에서 읽기 탭이 실제로 비활성 상태인 것을 확인했다. 알림은 1건 차단했고 주기 확인은 0회였다. 실제 탭 전환으로 복귀하자 브라우저의 활성화 이벤트에서 이전 화면을 비웠다. |
| 알림·활성화·주기 확인을 모두 지연 | 읽기 전용 화면에 이전 자료가 남아 있어도 JSON 백업을 누르자 저장소를 재확인하고 화면을 비웠다. 이전 자료는 다운로드되지 않았다. |
| 삭제 트랜잭션 실패 | 시험용으로 삭제 트랜잭션을 중단했다. 실패를 표시했고 삭제 전 화면과 저장소 해시가 유지됐다. |
| 재접속·새 작업 | 양쪽 탭의 새로고침과 같은 독립 프로필의 브라우저 재실행에서 비어 있었다. 새로 만든 프로젝트만 저장됐고 다시 열 수 있었다. |
| 삭제 범위 | 이미 내려받은 가상 백업의 SHA-256, 별개 IndexedDB·캐시의 검증 값, 앱의 정적 캐시가 유지됐다. |

독립 프로필의 9개 시나리오와 실제 탭 전환 시험이 모두 통과했고 앱 콘솔·페이지 오류는 없었다. 시험용 스크립트와 결과는 Git에서 제외되는 `tmp`에 보관했다. 이 단계에서는 다른 브라우저와 이전 앱 버전을 섞어 열어 둔 환경을 검증하지 않았다. 커밋·푸시·공개 배포·호스트 설정 변경은 하지 않았다.

## 후속 혼용 버전 검증

이 문서의 화면 비우기·출력 차단은 해당 수정이 적용된 탭을 대상으로 한다. 공개 구버전은 삭제 세대를 확인하지 않는다. 후속 수정의 IndexedDB 연결 버전 2 이행과 구버전 재저장 차단, 회수할 수 없는 구버전 메모리·JSON 백업의 범위는 [구버전·수정본 혼용 검증](mixed-version-reset-verification.md)에 별도로 기록한다. 연결 버전 변경은 기존 프로젝트의 스키마 변경이나 자동 전체 삭제를 의미하지 않는다.
